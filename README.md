# 期貨商活動看板

把 13 家期貨商官網「正在舉辦的活動」抓下來，彙整成一頁。
GitHub Actions 定時抓取，GitHub Pages 靜態託管。姊妹站是[期貨商公告看板](../futures-board)。

## 為什麼這件事比抓公告難

公告是一個列表頁換 N 筆結構化資料，抓到就結束。活動不是：

- **沒有列表**。活動幾乎只掛在首頁輪播 banner 上，沒有哪一家有完整的「活動總覽」頁。
- **文字在圖裡**。活動名稱、期間、獎勵通常整個做在 banner 圖與內頁大圖上，HTML 只剩免責條款。
- **有狀態**。活動會開始、會結束、會被撤掉，資料不是 append-only。

所以流程拆成三段，每段各自可除錯：**發現 → 判定 → 抽取**。

## 發現：banner 背後的連結

整套做法建立在一個觀察上——**活動文案在圖片裡，但連結還在 DOM 裡**，
所以不需要讀圖也拿得到候選。13 家共有四種接法，`lib/browser.mjs` 全部處理：

| 接法 | 範例 |
| --- | --- |
| `<a href>` 包住 `<img>` | 凱基、統一、國泰、華南 |
| 有 `background-image` 的容器，`<a>` 在裡面 | 元大 |
| `<a href="#" onclick="BLog(id,'<url>',…)">` | 國票 |
| DOM 裡根本沒有連結，資料來自 API | 康和（`sources/concord.mjs`） |

例外是台新：首頁輪播把 banner 內嵌成 base64 圖片、`<a href="">` 沒有目的地，
只能改抓他們的活動訊息 API（`sources/tsfutures.mjs`）。

輪播幾乎都是 JS 算出來的，所以**發現這一趟一律用 Chromium**；
落地頁則先用純 HTTP 讀，讀不動才升級成瀏覽器，整輪約 7 分鐘。

## 判定：哪些不是活動

分數夠高就收會收進一堆垃圾，實際踩到的坑：

- **得獎新聞稿**。凱基的「榮獲期貨鑽石獎第一名」banner 和活動 banner 長得一模一樣，
  內文也有「活動」「優惠」。→ 標題有得獎字樣又沒有活動期間就排除。
- **共用頁尾**。統一的 `/eventweb/` 底下每一頁都繼承同一份活動注意事項，
  所以 MultiCharts 教學網的分數跟真活動一樣高。
  → 收錄還要求「有活動期間」或「名稱長得像活動」（…禮／…賽／…回饋／…季／加碼／好禮）。
- **常設方案**。群益的贏家名人堂、華南的線上開戶頁都在活動路徑上，但沒有起訖。
  → 同上，被名稱規則擋掉。
- **陳年活動**。大昌首頁還掛著 2022 年的 banner，國票有 2015 年的活動頁。
  → 網址與 banner 檔名裡的日期（`EventWeb/20220118/`）當作發佈日；
  超過 9 個月又讀不到活動期間就視為已結束。
- **渲染失敗**。逾時的頁面和「純圖片活動頁」在長度上看起來一樣。
  → 只有「瀏覽器真的渲染完成、文字很少、但圖片不只一張」才算純圖片活動頁。

## 抽取：規則，不用模型

`lib/extract.mjs` 是這個專案最需要養的檔案。刻意不接 LLM，讀不到就誠實留白：

- **標題**取自落地頁 `<title>`，這是最可靠的欄位——文案做進圖裡了，但標題幾乎都寫著活動全名，
  有時連獎勵都在（`凱基期貨｜登記享專人開戶陪跑，最高領 $1700 交易應援金！`）。
  只有公司名的標題會被略過，改用 `<h1>` 或 banner 的 alt。
- **期間**先在「活動期間」附近找，找不到才全頁掃。處理民國年、`2026/08/01～12/31`
  這種省略年份的寫法（會跨年進位）、中文年月日、`2026年7-12月` 這種整月區間。
  頁面上的開獎日、最後交易日不會被誤讀。細節見下節。
- **獎勵**只認帶幣別標記的數字（`NT$1,700`、`600元`、`10萬元`），
  且要在獎勵字眼附近、不在保證金／稅額／口數門檻的語境裡。
  沒有這層限制的話，`2026/04/15` 會被讀成 NT$2,026。

**讀不出來時，卡片改秀 banner 原圖**——本來就是設計給人看懂的。
這類活動會列進「無法辨識」分頁，明講讀不到哪個欄位並連到原始活動頁，由人自己判讀。

## 期間讀錯：一種會偽裝成成功的失敗

抓不到活動很容易發現，**讀錯期間不會**——活動照樣出現在看板上，只是日期是錯的，
甚至被判成已結束而從「進行中」消失。實際發生過兩次，兩次都是把頁面上*別的*日期當成活動期間：

- **華南 賞金盛典**改版成 115/08/01–11/30 新一季，但頁面前段仍以資格定義的形式引用舊檔期
  （`*新動用戶定義: 活動期間全新戶或115/1/1-7/31未交易…`）。依出現順序讀就讀到舊的，
  把首頁第一張 banner 的活動判成已結束。
- **永豐 海期掏金季**實際跑 `2026年7-12月`，但頁面另有
  `2026/01/01~06/30 海外期貨無任何交易筆數,即符合靜戶定義`，被當成活動期間。

三層修正：

1. **標題位置勝過句中引用。** 收集頁面上*所有*標了「活動期間」的位置再排序，
   而不是取第一個。標題後面接的是冒號或換行，句子後面接的是下一個字——這一個差別就分得開。
2. **資格用的日期不算期間。** 日期所在*句子*出現「定義／未曾交易／靜戶／舉例」等字眼就排除。
   用句子而非固定字元窗，否則相鄰句子的「未曾交易」會誤傷正確答案。
3. **矛盾要浮上來。** 活動還掛在該期貨商首頁輪播、卻被判定已結束，就標記 `suspect`：
   終端輸出用 ⚠ 列出來，卡片上也顯示紅色提示。這層不依賴規則寫得對不對——
   永豐那筆就是加了這個檢查當下立刻被抓出來的。

另外，同一頁若出現兩組同樣是標題形式的期間，會標記 `ambiguous`、信心降一級並在卡片上註明。

## 收錄的期貨商

看板依名稱筆劃排序（與公告看板同一套順序）：
大昌／元大／台新／永豐／兆豐／康和／國泰／國票／統一／富邦／華南／凱基／群益。

## Facebook 與只發在社群的活動

**不做自動爬取**。Graph API 讀不到別人的粉專（需 Page Public Content Access，
要 app review 加商業驗證）；直接爬違反 ToS，且 GitHub Actions 的 IP 幾乎必定被擋。

替代做法是 `seeds.yml`：看到 FB 上的活動，貼一行網址進去就好，
它會走完全一樣的判定與抽取流程。

## seeds.yml

補進爬不到的活動用的，改完存檔就生效，不必動程式：

```yaml
add:                  # 抓不到的活動（只發在 FB、需登入、官網沒掛連結）
  - broker: kgi
    url: https://event.kgi.com.tw/...
    start: 2026-08-01 # 選填，讀得到就不用寫
    maxValue: 1700    # 選填
    note: 僅發布於 Facebook

block:                # 一直被誤判成活動的網址
  - https://www.example.com.tw/not-a-campaign
```

還有一個 `override:` 區塊可以覆寫個別欄位（`start` / `end` / `maxValue` / `title`），
但**「無法辨識」清單刻意不引導你去用它**：讀不出來的活動辦法幾乎都在圖片裡，
與其把人工判讀的結果抄進 repo 再慢慢過期，不如點進原頁面看。
`override` 留著是給真的讀錯、需要立刻壓過去的情況。

## 功能

- **時間軸**：一列一檔，橫條是活動期間，今天一條紅線。活動有起訖，這是它該有的視覺。
- **卡片**：依期貨商分組，13 家都會列出，沒有活動的也列。
- 讀不出期間或獎勵的活動，會在自己的卡片上直接寫明「無法辨識什麼」並連到原始活動頁，
  由人點過去自己判讀。沒有另開清單——同一件事講兩次只是多一份要維護的東西。
- 篩選：狀態、新戶可參加、依結束日／最高獎勵／期貨商排序。
- **日夜模式**跟隨系統，可手動切換；**字體五段**可調。兩者都記在 localStorage。
  淺色與深色的所有文字對比度都實測在 4.5:1 以上（WCAG AA）——包含期貨商色標籤與
  時間軸長條，那兩處的明度是分別為兩種主題各自指定的，因為同一個明度不可能兩邊都能讀。
- **banner 圖存進 repo**，不是 hotlink——元大、永豐、凱基、群益的圖都擋跨站載入，
  而圖片正是讀不到欄位時的替代品，破圖等於整張卡片沒了。
  存檔前用 Playwright 的 canvas 轉成 **WebP 640px**（省下一個原生影像相依）。
  期貨商出的圖是 1920px、2–4 MB，卡片只顯示約 400px 寬，等於原圖大了五到五十倍；
  轉完 11 張合計約 270 KB。

視覺參考 KKday：淺色為底、珊瑚色重點、圓角卡片。與夜間看板的 公告看板 相反，
因為這個站是白天在決定要不要開戶時看的，不是半夜盯部位時看的。

## 本機使用

```bash
npm install
npx playwright install chromium
npm run scrape      # 抓取，寫入 site/data.json 與 site/banners/
npm run serve       # http://localhost:4322
npm test            # 規則的迴歸測試，不連網
```

只抓特定幾家：

```bash
node scripts/scrape.mjs kgi yuanta --verbose
```

單獨追一個網址，看它被怎麼判讀：

```bash
node scripts/inspect.mjs https://www.yuantafutures.com.tw/2026CME/ --text
```

## 部署設定

網站：<https://hahabao-tw.github.io/13futures-activity/>

在**台灣時間週一到週五 01:15** 抓一次。活動的變動以週為單位，一天一次綽綽有餘；
週末期貨商不會上架新活動，跑了也只是重複。深夜也避開了整點與白天的尖峰。

> cron 寫成 `15 17 * * 0-4`。GitHub 只吃 UTC，台灣是 UTC+8，往前推 8 小時會落在
> **前一天** 17:15，星期也跟著往前挪一天——台灣的週一到週五對應 UTC 的週日到週四，
> 所以是 `0-4` 而不是 `1-5`。

寫出來的東西分兩份：

| 檔案 | 何時改寫 | 用途 |
| --- | --- | --- |
| `site/data.json` | 只在活動真的有異動時 | 內容。每一筆 commit 都代表某家真的改了活動 |
| `site/status.json` | 每次執行都改寫 | 這次跑了、跑到哪、哪幾家失敗 |

分開有兩個好處。網站頁尾可以同時顯示「資料更新」與「上次檢查」——
**看板一個月沒變**跟**抓取一個月前就掛了**，從外觀上完全一樣，只有後者能分辨；
超過 36 小時沒成功抓取，頁面會直接跳紅字警告。

第二個好處是每次執行都會產生一筆 commit，
**GitHub 對「連續 60 天沒有活動就自動停用排程」的規則因此不會觸發**。
commit 訊息會區分「更新活動資料」與「例行檢查，活動無異動」，方便從歷史裡挑出真正的變動。

**換一個 repo 時，Pages 要先自己開一次。** workflow 裡沒有用 `configure-pages` 的
`enablement: true`：建立 Pages 站台需要 repo 的 admin 權限，而 GITHUB_TOKEN 不論宣告
多少 permissions 都沒有，只會得到 `Resource not accessible by integration`。
到 **Settings → Pages** 把 Source 設成 **GitHub Actions**，或跑一次：

```bash
gh api -X POST repos/<owner>/<repo>/pages -f build_type=workflow
```

> GitHub Pages 上的內容是公開的。這裡只有各期貨商官網本來就公開的活動標題、期間與連結。

```
  scrape.mjs            主控：發現 → 判定 → 抽取 → 與上次合併
  inspect.mjs           單一網址除錯：讀到什麼、怎麼評分、抽出什麼
  serve.mjs             本機預覽用的靜態伺服器
  test.mjs              規則迴歸測試（38 項，全離線）
  lib/browser.mjs       Playwright：通用 banner 採集、落地頁渲染、圖片縮放
  lib/landing.mjs       落地頁讀取，HTTP 優先、必要時才開瀏覽器
  lib/classify.mjs      是不是活動：預篩、評分、最終確認
  lib/extract.mjs       規則抽取：標題／期間／獎勵／對象／商品
  lib/banners.mjs       banner 圖下載、縮放、清除沒人用的舊圖
  lib/seeds.mjs         seeds.yml 的載入與欄位覆寫
  lib/http.mjs          fetch 包裝：重試、逾時、Big5 解碼
  lib/util.mjs          正規化、日期、狀態判定、網址正規化
  sources/index.mjs     13 家的首頁、活動網址樣式、筆劃排序
  sources/concord.mjs   康和：banner 沒有 href，改讀他們的 banner API
  sources/tsfutures.mjs 台新：banner 沒有目的地，改讀活動訊息 API
site/
  index.html app.js style.css
  data.json             活動內容（由 CI 回寫，只在有異動時）
  status.json           每次執行的時間與各家成敗（由 CI 回寫，每次都寫）
  banners/              各活動的 banner 縮圖（由 CI 回寫）

```

## 維護

期貨商改版時，該家會抓到 0 筆——但 0 筆也可能只是他們現在真的沒活動，
兩者從看板上分不出來。要確認時單獨跑那一家看候選清單：

```bash
node scripts/scrape.mjs <該家id> --verbose
```

候選數掉到個位數就是採集壞了，候選還在但全被跳過就是判定規則需要調。
先改 `lib/classify.mjs` 或 `lib/extract.mjs`，並在 `scripts/test.mjs` 補一條測試把它釘住。

每次抓取結尾的 **⚠ 區塊**是最該看的一段：列出「仍掛在首頁輪播、卻判定已結束」的活動。
這是期間讀錯唯一會自己冒出來的訊號，出現就代表有東西要查。

### 時間預算

三層，全部在 `config.mjs`。理由是實際發生過一次：統一的某個頁面卡在
`page.evaluate` 裡不動，Playwright 自己的逾時管導覽與操作、**但不管 evaluate**，
於是整輪抓取在那一頁上耗掉 23 分鐘，其餘 12 家全部陪葬。

| 層級 | 預設 | 超過時 |
| --- | --- | --- |
| 單一頁面 `PAGE_BUDGET_MS` | 75 秒 | 關掉分頁（關頁面才真的解得開卡住的 evaluate） |
| 單一候選 `CANDIDATE_TIMEOUT_MS` | 90 秒 | 略過這則，該家繼續 |
| 單一期貨商 `BROKER_BUDGET_MS` | 5 分鐘 | 剩下的候選不檢查，換下一家 |
| 整輪 `GLOBAL_BUDGET_MS` | 20 分鐘 | 未抓的期貨商標為失敗，沿用上次資料並顯示 ⚠ |

最後一層是為了配合 CI 的 `timeout-minutes: 30`：job 被逾時砍掉的話什麼都不會寫，
連「這幾家沒抓到」都留不下來；提早收手才記得住。

## 免責

資料由程式自動判讀，可能誤判或遺漏；僅發布於社群平台的活動不在自動收錄範圍。
